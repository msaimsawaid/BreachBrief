## 1. Overall architecture
`Flask app → background job (ThreadPoolExecutor) → 8-phase pipeline → in-memory result → report rendered on demand.`
- No database, no queue service, single process. Can swap for Redis/a real queue if this becomes multi-instance.

## 2. The pipeline
`ingest → parse → normalize → correlate → mapping → risk → evidence_reasoning → timeline`
- Risk scoring runs before `evidence_reasoning` because it needs `confidence_breakdown`, which risk.py computes.
- Evidence reasoning runs after mapping because it needs the MITRE technique already resolved onto the group.

## 3. Ingestion / parsing
- Wazuh `alert_json` & `raw_logs`, Detection is a cheap heuristic: first non-whitespace char is `{` or `[` → JSON, else log.
- Once a file's lines/records are parsed into events, the ingested object drops them.

## 4. Correlation
- Grouping is per event, not per event-type. An event type (Privilege Escalation) is grouped by (type, source_ip) in a rolling time window, only if it has a real attacker IP. Otherwise it falls back to (type, rule_id, agent) grouping with no time window.
- Why not just window everything the same way? fixed mode table explodes into thousands of singleton groups.

## 5. Risk scoring — expect the deepest questions here
`RiskScore = SeverityBase × ConfidenceFactor × ImpactMultiplier + FrequencyBonus`
- SeverityBase: 15/40/65/90 for low/med/high/critical — the dominant term, deliberately, so one Critical finding can hit the High band on severity alone.
- ConfidenceFactor: built from how the event was classified structured Wazuh metadata beats keyword-guess beats unclassified.
- ImpactMultiplier: modest swing by harm category (exfil/lateral-move/priv-esc weighted up).
- FrequencyBonus: log-scaled, repetition nudges a score, it can't dominate it.

## 6. Evidence reasoning
The four-part structure to know: `observed` (literal facts only) / `derived` or `inferred` (explicitly labeled as a guess) / `not_observed` (states what evidence would need to exist to escalate further).

## 7. Framework enrichment
Not just MITRE — mapping.py covers MITRE ATT&CK, CWE, OWASP Top 10, NIST CSF, and CIS Controls, keyed per event type (~20 types covered). CVE IDs are pulled straight from extracted alert data, not looked up.

## 8. Reporting
- Two output formats: DOCX (python-docx) and PDF (reportlab, `SimpleDocTemplate`).
- Four report modes: analyst / executive / soc / forensic — same underlying data, different verbosity/audience framing.
